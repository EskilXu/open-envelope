OpenEnvelope 术语辞典

参考架构页上出现过的每一个专有名词：它是什么、谁维护、在架构里坐哪个位置

每条末尾的 位置 指该名词在参考架构图 1 中的所在列或所交换的层（L0 Envelope / L1 Position / L2 Offer / L3 Attestation）。置信标记只针对"该组织/标准的事实描述"，不针对本标准的设计判断。

§0本标准自己的对象

OpenEnvelope暂定名
本参考架构描述的开放、中立的灵活性资源交换标准。名字取自"flexibility envelope（灵活性包络）"这一既有学术术语；日语工程界称運転エンベロープ，中文称可行域包络。四层对象 + 聚合语义 + 规则集 + 一致性测试。位置 图 1 中央总线
EnvelopeL0
"一个时间窗内，一台或一群资源能做什么"的可行域描述：时间窗、变量上下界、线性约束集 A·u ≤ b、模式变量、命名参数（储能、爬坡）、回退方式、同意声明、来源。它描述能力，不描述打算。位置 由资源管理器发布，聚合商读取
PositionL1
包络内的一条具体轨迹：schedule（计划）、cleared（市场成交后的计划）、measured（计量实测）。三者同格式，便于逐点比较。位置 总线上双向流动；计量数据回流为 measured
OfferL2
对一个 Envelope 的市场包装：价格、可否分割、最低接受比例、关联/互斥报价组、市场引用。它引用 L0 而不复制 L0。位置 聚合商写，经交易所/系统运营者协议提交
AttestationL3
校验结果的证明对象：被检对象引用、输入哈希、规则集 id 与版本、结论（pass / fail / inconclusive）、违规清单、检查时间、签名。任何人可用同一输入与规则版本复算。位置 校验服务写；透明日志存；请求方持有
Envelope 适配器
把既有协议（S2、IEEE 2030.5、OCPP、OPC UA、IEC 61850…）的语义映射为 L0/L1 对象的开源组件；反向把 L1 schedule 变为设备可懂的设定值。映射规则是标准的一部分。位置 资源管理器内
Envelope 总线
抽象概念，不是具体消息中间件：任何能承载四层对象的方式（文件、REST、消息队列）都算。总线上只允许出现四层对象。位置 图 1 中央
consent同意声明
L0 上的三个字段：cross_border（可否出境）、training_use（可否用于训练）、retention_days（保留期）。未声明视为全部禁止。规则 consent.scope 检查请求上下文与之一致。位置 L0；影响图 1 右下"开放数据集"的虚线路径
provenance来源
每个对象必带的元数据：数据来自哪里、何时取得、许可条款、生成工具、原始记录引用。让每个数字都能追到源头。位置 所有四层
ext扩展命名空间
核心 schema 之外的字段容器，按反向域名命名（如 ext["lfenergy.cds"]）。任何人可注册命名空间，无独占。市场特定字段（例如某国的报价形式）放这里，不进核心。位置 所有四层
{scheme, id}命名空间标识
本标准不发明任何编码。所有标识写成"发码机构反向域名 + 该机构原码"，如 {"scheme":"iec.cim.mrid","id":"…"}。这样可以同时引用欧洲的 EIC、各国系统运营者的区域码、变电站的 CIM 标识而不冲突。位置 L0 resource_ref

§1设备侧协议（图 1 左列、图 1b）

S2EN 50491-12-2★
欧洲标准（CENELEC，2022 批准），定义建筑内"客户能源管理器（CEM）"与"资源管理器（RM）"之间如何沟通设备灵活性。由 FAN 主导开发，有开源 JSON schema 与多语言实现。它是 L0 在户内/楼宇层的最近亲：S2 告诉 CEM 设备能怎么动，Envelope 把这件事带到楼宇之外。位置 储能、可控负荷 → 资源管理器
FRBC / OMBC / PEBCS2 控制类型★
S2 的三种主要控制模型。FRBC（Fill Rate Based Control）用"填充率"描述带储量的设备（电池、热水箱、EV），含存储描述与填充水平；OMBC（Operation Mode Based Control）用离散运行模式描述设备，是 L0 中 mode 变量的直接来源；PEBC（Power Envelope Based Control）直接给出功率包络。三者都能无损映射进 L0。位置 L0 生成
IEEE 2030.5Smart Energy Profile 2.0◆
IEEE 标准，基于 HTTP/REST 与 XML 的 DER 通信协议，定义 DER 能力（DERCapability）、设定（DERSettings）、状态（DERStatus）、计量镜像点等资源。美国加州（CSIP）与澳大利亚（CSIP-AUS）作为逆变器并网的强制接口。LF Energy 的 CUPID 是其开源实现。位置 分布式发电、储能 → 资源管理器；DERCapability → L0 bounds
CSIP / CSIP-AUSCommon Smart Inverter Profile◆
IEEE 2030.5 的实施规范（profile）：规定用哪些资源、什么安全模型、什么消息节奏，使不同厂商互操作。加州版由 SunSpec 联盟维护；澳大利亚版由 DER 集成专家小组维护。位置 同 IEEE 2030.5
SunSpecSunSpec Alliance◆
光伏/储能行业联盟，维护基于 Modbus 的逆变器信息模型（SunSpec Modbus）与 CSIP。图 1 中作为光伏侧的既有数据模型。位置 分布式发电
Modbus◆
1979 年起的工业串行/TCP 协议，寄存器读写，无信息模型、无安全。仍是大量逆变器、电表、PCS 的事实接口。适配器需要外部字典（如 SunSpec）才能把寄存器变成 L0。位置 设备侧遗留接口
BACnetISO 16484-5◆
楼宇自动化协议（暖通、照明），ASHRAE 维护。热泵、空调类可控负荷常经 BACnet 暴露。位置 可控负荷
OCPPOpen Charge Point Protocol◆
充电桩与充电运营商后台之间的开放协议，Open Charge Alliance 维护，2.0.1 起支持智能充电曲线与 ISO 15118 集成。LF Energy 的 EVerest 是其开源实现。位置 电动车/充电桩 → 资源管理器
ISO 15118◆
车辆与充电桩之间的通信标准，含即插即充身份认证与双向充放电（-20）。它提供 EV 的离场时间、目标电量等信息——正是生成每桩 L0 所需的参数。位置 电动车 → L0 生成
IEC 61850◆
IEC TC57 的变电站与电力自动化通信标准族。核心是信息模型：7-3 公共数据类（CDC）、7-4 逻辑节点（LN）、7-420 DER 专用逻辑节点；SCL（系统配置语言）描述整站配置。发电机组、变电站、大型 DER 的额定值、限值、状态都在这里。位置 常规机组/抽蓄 → 资源管理器；SCL → 网络模型来源
OPC UAIEC 62541◆
OPC Foundation 维护的工业互操作架构：一个面向对象的地址空间（信息模型）+ 服务（浏览、读写、订阅、方法调用）+ 多种传输绑定。与 Modbus 不同，它自带类型系统与安全模型。本标准把 Envelope 做成它的一个 companion 信息模型（图 1b）。位置 可控负荷、数据中心、常规机组 → 资源管理器
OPC UA PubSubPart 14◆
OPC UA 的发布/订阅传输模式，可走 UDP 多播或 MQTT，用于高频、一对多的数据推送。图 1b 中 L1 measured 经此推送。位置 设备 → 适配器
Companion SpecificationOPC UA 伴随规范◆
OPC Foundation 与行业组织联合发布的领域信息模型（如机床、机器人、注塑机），定义该领域的对象类型与变量，使不同厂商设备在 OPC UA 上"说同一种话"。本标准提议的 EnvelopeType 即属此类。位置 图 1b
OPC UA for IEC 61850◆
已有的 companion 规范（2018 发布候选），把 61850-7-4 全部逻辑节点与 7-3 公共数据类映射进 OPC UA 对象。意义：工厂里同一套 OPC UA 系统可以同时看到工艺数据与电气数据。对本标准：DER 节点的额定与限值可机器读出，直接作为 L0 bounds 来源。位置 图 1b 右上
RedfishDMTF◆
数据中心硬件管理的 REST/JSON 标准（服务器、电源、机柜），DMTF 维护。数据中心作为大负荷时其电源遥测经此暴露；不属本标准范围，只作为站点级 L0 的输入来源之一。位置 数据中心 → 资源管理器
NATS◆
云原生的轻量消息系统（CNCF 项目）。LF Energy 的 CUPID 用它承载 IEEE 2030.5 消息以取代纯 REST 轮询。出现在此仅因 CUPID 使用它。位置 CUPID 内部

§2市场与运营侧协议（图 1 右列）

IEC 62325 CIM市场通信 CIM◆
IEC TC57 的能源市场通信标准，是 CIM（公共信息模型）在市场侧的部分。62325-451 系列定义欧洲式市场文档：Bid_MarketDocument（报价）、Schedule_MarketDocument（计划）、Publication_MarketDocument（公布结果）等，含 block bid、linked bids、exclusive bids 的既有语义。本标准 L2 直接映射，不重定义。位置 聚合商 ↔ 交易所 / TSO
CIMCommon Information Model · IEC 61970/61968/62325◆
电力行业的统一数据模型：61970 输电、61968 配电、62325 市场。mRID（master resource identifier）是其中每个对象的全局唯一标识，本标准用 {"scheme":"iec.cim.mrid"} 引用它来指节点与设备。位置 resource_ref · 网络模型
Shapeshifter原 UFTP◆
LF Energy 项目，源自荷兰 USEF 框架的"USEF Flex Trading Protocol"：定义聚合商与配电/输电运营者之间的灵活性请求（FlexRequest）、报价（FlexOffer）、订单（FlexOrder）、结算（FlexSettlement）消息。本标准的 L2 可作为 FlexOffer 的载荷，FlexOrder 映射为 L1 cleared。位置 聚合商 ↔ DSO/TSO
USEFUniversal Smart Energy Framework◆
荷兰产业联盟提出的灵活性市场角色与流程框架，定义聚合商、BRP、DSO 之间的互动。UFTP 是其协议部分，后捐给 LF Energy 成为 Shapeshifter。位置 背景
OpenADR 3Open Automated Demand Response◆
OpenADR Alliance 的需求响应协议，3.0 版改为 REST/JSON，核心对象是 program（项目）、event（事件）、report（报告）、priceMap（价格）。事件驱动，适合"某时段请削减"类信号；不表达可行域。LF Energy 的 OpenLEADR 是其参考实现。位置 DSO → 聚合商；event → L1 上下文，priceMap → L2 price

§3基础数据与许可规范

JSON Schema 2020-12★
描述 JSON 文档结构与约束的规范，2020-12 是当前草案版本。四层对象的 schema 均以此编写；校验流水线第一步即按它验证。位置 图 3 ①
SHA-256input_sha256★
密码学哈希函数，输出 64 个十六进制字符。对规范化后的输入求哈希，得到 L3 中的 input_sha256——它是"我检查的确实是这份文件"的指纹，也是复算路径的比对键。位置 图 3 ②
规范化canonicalization
把语义相同但写法不同的 JSON（键顺序、空白、数值表示）变成唯一字节串，否则同一份计划会得到不同哈希。位置 图 3 ②
ISO 8601★
日期时间表示标准。本标准要求所有时间带时区偏移（如 2026-09-04T12:00:00+09:00），杜绝"本地时间"歧义。位置 所有 window 字段
ISO 4217★
三字母货币代码（JPY、EUR、USD）。L2 price.currency 用它。位置 L2
EICEnergy Identification Code · ENTSO-E◆
ENTSO-E 维护的 16 位标识码，用于欧洲内部市场的参与方、区域、资源。由中央发码办公室与各国本地发码办公室颁发；范围限于欧洲，无日本等地办公室。因此本标准不以它为唯一全球码，而以 {scheme,id} 引用。位置 resource_ref（欧洲）
Apache-2.0★
宽松开源软件许可，含明确的专利授权条款——贡献者授予使用者其贡献所涉专利的许可。本标准的 schema、适配器、校验器、测试均采用。选择它而非 MIT 正是为了专利条款。位置 治理
CC BY 4.0★
知识共享"署名"许可：任何用途（含商业）均可，只须署名。用于规范文本与开放数据集。刻意不用 NC（非商业）变体——NC 会让企业不敢在生产中使用。位置 治理 · 开放数据集

§4LF Energy 托管项目（§2b 表）

FlexMeasures★
开源能源管理/调度平台（Python），用"flex-context"描述系统层面的目标与价格，用"flex-model"描述每台设备的能力（power-capacity、soc-minima/maxima/targets、group 共享容量、S2 power bands），内部用 Pyomo 或 HiGHS 求解混合整数线性规划。其资产树天然对应本标准的五级层级。本标准首选的第一个外部实现对象。位置 资源管理器 · 聚合商优化器；L0 ⇄ L1
OpenLEADR◆
OpenADR 的开源参考实现（Python），支持 2.0b 与 3。位置 DSO ↔ 聚合商事件边界
EVerest◆
开源电动车充电固件栈，实现 OCPP、ISO 15118 等，可直接跑在充电桩控制器上。它掌握每个充电会话的车辆需求，是生成充电桩 L0（含充/放/停模式）的自然位置。位置 电动车/充电桩
CUPIDControllable Unit Protocol Interface for DER◆
2026 年加入 LF Energy 的 DER 互操作工具包，源自欧盟资助的 InterStore 项目：IEEE 2030.5 客户端/服务端（经 NATS 传输）、遗留协议转换器、自动化测试工具。曾在意、德、葡、奥四个试点部署。位置 光伏/储能/逆变器 → L0 生成
CoMPASConfiguration Modules for Power industry Automation Systems◆
IEC 61850 配置工具（SCL 文件的生成与校验）。SCL 中的机组额定与拓扑可作为 L0 bounds 与校验用网络模型的来源。位置 变电站/机组侧；L0 来源
SEAPATHSoftware Enabled Automation Platform And Artifacts (THerein)◆
变电站自动化的开源虚拟化平台（实时 Linux + 虚拟机/容器），让 IEC 61850 应用跑在通用硬件上。校验服务的边界内部署（拓扑 A）可落在这类平台上。位置 变电站侧
Power Grid Model◆
高性能配网/输网稳态计算库（C++ 核心，Python 接口）：潮流、状态估计、短路。可作为 R-PHYS 规则组比直流潮流更强的后端（交流潮流）。位置 校验服务内部
PowSyBlPower System Blocks◆
Java 电网建模与仿真框架（源自法国 RTE），支持 CIM/CGMES 导入、潮流、安全分析（N-1）、动态仿真。同样可作 R-PHYS 后端，尤其 N-1。位置 校验服务内部
OpenSTEFShort Term Energy Forecasting◆
短期负荷/发电预测流水线（Python，机器学习）。预测是生成 L0 的输入之一，但不是标准对象——列出它是为了划清边界。位置 聚合商内部；不对接
OperatorFabric◆
电网运营者的通用告警/卡片界面框架：把来自各系统的事件整理成需要人处理的"卡片"。L3 verdict=fail 生成卡片是它在本架构中的自然落点。位置 系统运营者；L3 → 人
URPXUtility Rate Plan eXchange◆
2026 年加入 LF Energy 的公用事业费率计划数据交换标准。费率结构复杂（分时、阶梯、需量），本标准借用它而不自定义。位置 L2 price 上下文
AINETUS◆
2026 年加入 LF Energy 的电网运行 AI 决策支持项目。系统级 L0 外近似可作其输入；L3 可作其建议可信度的证据。本标准不介入其决策逻辑。位置 系统运营者
Carbon Data SpecificationCDS◆
LF Energy 的电网碳强度/排放数据规范。经 ext["lfenergy.cds"] 挂到 Envelope 上，不进核心层。位置 ext
Sandbox · Incubation · GraduatedLF Energy 项目阶段◆
Linux Foundation 系基金会通用的项目生命周期：沙箱（早期，门槛低）→ 孵化（有多组织贡献、有治理）→ 毕业（成熟、被广泛采用）。本标准的托管目标路径。位置 治理

§5组织与机构

LF Energy★
Linux Foundation 下属的能源开源基金会（2018 年成立），托管上节所有项目，成员含欧洲多家输配电运营者、软件厂商与研究机构。每年办 LF Energy Summit（2026 年欧洲峰会 9 月 15 日于柏林）。本标准的目标托管方。
Linux Foundation★
非营利技术联盟，托管 Linux 内核及数百个开源项目与子基金会（CNCF、LF Energy 等），提供中立的治理与法律框架。
OPC Foundation◆
维护 OPC UA 及其 companion 规范的行业联盟（1996 年成立）。companion 规范由其与领域组织组成联合工作组发布。本标准的 EnvelopeType 若要成为正式 companion，须经此路径。
IEC TC57◆
国际电工委员会第 57 技术委员会"电力系统管理与信息交换"，负责 IEC 61850、61970/61968（CIM）、62325（市场 CIM）、62351（安全）等。本标准引用其模型，不与之竞争。
ENTSO-E◆
欧洲输电系统运营者联盟，维护 EIC 编码、CIM 市场 profile 的欧洲实施、透明度平台。
FANFlexiblepower Alliance Network◆
荷兰起源的产业联盟，S2 标准的主导开发者，维护 s2-json 等开源实现。
CENELEC◆
欧洲电工标准化委员会，欧洲标准（EN）的发布机构；S2 的正式编号 EN 50491-12-2 由此而来。
IEEE★
电气电子工程师学会，标准协会发布 IEEE 2030.5、1547（DER 并网）等。
OCPOpen Compute Project◆
数据中心硬件开放设计基金会（机柜、电源、服务器）。目前没有面向电网的灵活性接口规范 ◇；数据中心在本架构中作为"站点"级 Envelope 对接。
DMTF◆
分布式管理任务组，Redfish 的维护者。
Open Charge Alliance◆
OCPP 的维护组织。

§6市场角色（图 1 各列）

资源管理器EMS · CEM · RM
站点/楼宇/园区一级的能源管理系统。S2 语境中分为 CEM（客户能源管理器，做决策）与 RM（资源管理器，代表设备）；本架构统称资源管理器，它是 Envelope 适配器的宿主，也是回退规则库所在。位置 图 1 第二列
回退规则库fallback rulebook
离线预先计算并固化的保守安全策略：当上层计划缺失、超时或校验失败时，设备按规则库运行而不依赖在线优化或推理。原则："刹车不能依赖油门的健康"。L0 的 fallback 字段引用它。位置 资源管理器
聚合商Aggregator · VPP

售电公司 · BRPBalance Responsible Party
向终端用户售电的零售商；BRP 是欧洲术语，指对自己组合的"计划与实际一致"负财务责任的主体（日本称"计划值同时同量"义务）。偏差按不平衡费结算。位置 图 1 第四列
批发电力交易所
日前/日内电能交易平台（如 EPEX、Nord Pool、JEPX）。接受报价、出清、公布价格。本架构中 L2 经交易所 API 或 CIM 提交，成交回流为 L1 cleared。位置 图 1 右列
平衡 / 调节力市场
系统运营者采购实时平衡能力（备用、调频）的市场。资源须在被调用时真的能动——这正是校验 L1 ∈ L0 的价值所在。位置 图 1 右列
DSO配电系统运营者
负责中低压配电网的运营者。关心馈线/变压器是否过载，是 Shapeshifter、OpenADR 的主要对手方，也是 L0 外近似的接收者。位置 图 1 右列

计量数据管理
智能电表数据的采集、校核与分发方（各国制度不同：可能是 DSO、独立机构或市场运营者）。其数据是 L1 measured 的权威来源。位置 图 1 右下

§7电力物理与数学

KCL基尔霍夫电流定律
任一节点流入电流之和等于流出之和。在功率层面：节点注入 − 负荷 − 净支路流出 = 0。规则 phys.kcl 计算每节点残差。位置 R-PHYS
KVL基尔霍夫电压定律
任一闭合回路电压降之和为零。在直流潮流近似下：支路流量乘电抗，沿环路求和为零；等价于存在一组节点相角 θ 使 X·f = A·θ。规则 phys.kvl 用最小二乘求残差。位置 R-PHYS
直流潮流DC power flow
交流潮流的线性化近似：忽略电阻与无功，假设电压幅值为 1、相角差小。计算极快、无收敛问题，适合校验与市场出清；代价是看不到电压与无功问题。本标准基础规则集用它；可换 Power Grid Model / PowSyBl 的交流潮流。位置 R-PHYS 方法
交流潮流AC power flow
完整的非线性潮流方程（有功、无功、电压幅值、相角），需迭代求解（牛顿-拉夫逊）。更准，但可能不收敛。位置 R-PHYS 可选后端
N-1安全准则
任一单一元件（线路、变压器、机组）故障退出后，系统仍应无过载、无失稳。PowSyBl 的安全分析可做此校验。位置 R-PHYS 可选
线路限额 · 支路流
每条线路/变压器允许的最大功率（热极限或稳定极限）；支路流是流经它的功率。规则 phys.limit 逐支路比较。位置 R-PHYS
节点相角 θ
直流潮流中每个节点电压的相位角；相角差驱动功率沿线路流动。其存在性即 KVL 成立的判据。位置 phys.kvl
最小二乘残差
找一组 θ 使 X·f − A·θ 的平方和最小；剩下的量就是"无论怎么选相角都解释不掉的部分"，即 KVL 违反量。位置 phys.kvl 方法
约束集 A·u ≤ b线性不等式组
用矩阵 A、向量 b 描述的可行域：所有满足全部不等式的功率序列 u 都"做得到"。几何上是一个凸多面体（polytope）。这是 L0 的核心表示，也是"字段式"表示的一般化。位置 L0
模式变量 · 整数约束mode / binary
只能取离散值的变量（开/关、充/放/停），以及依赖它们的约束（最小持续时间、最大切换次数、起动费用）。线性不等式表达不了它们，故 L0 需单独的 modes 定义，规则 env.mode 枚举检查。位置 L0 · R-ENV
SOCState of Charge
储能当前电量占容量的比例（0–1）。SOC 轨迹由功率序列、效率、初始值前向积分得到；规则 env.soc 检查它是否始终在 [soc_min, soc_max] 内。位置 L0 params.storage · R-ENV
爬坡ramp
功率在相邻时步之间的最大变化量。L0 用 diff 约束表达，规则 env.ramp 检查。位置 L0 · R-ENV
Minkowski 和
两个集合 A、B 的 Minkowski 和是 {a + b : a∈A, b∈B}。多个资源可行域的聚合正是它们的 Minkowski 和；精确计算在高维下不可行，故实际只能取内近似或外近似。位置 图 2 · R-AGG
inner / outer / exact近似声明
inner（内近似）⊆ 真实可行域：承诺的每一点都能兑现，用于向系统运营者承诺。outer（外近似）⊇ 真实可行域：不泄露内部结构，用于对市场公布可用性，但成交后须能分解。exact 仅当下级全为盒约束且无耦合时成立。L0 聚合时必须声明其一。位置 图 2 · agg.approx
盒约束box constraint
每个变量独立的上下界、彼此无耦合（像一个长方体）。盒约束的 Minkowski 和可以精确算（上下界分别相加），是 exact 声明的前提。位置 agg.approx
分解disaggregation
把上级成交的 L1 拆成各下级的 L1ᵢ。规则 agg.sum 要求 Σ L1ᵢ = L1 且每个 L1ᵢ ∈ L0ᵢ。位置 图 2 · 图 4 ⑥
Block / linked / exclusive报价类型
交易所报价语义：block 多时段捆绑、全量成交或全不成交；linked 子报价成交以父报价成交为条件；exclusive group 组内最多一个成交。源自欧洲交易所与 CIM 62325。规则 mkt.links 检查其图结构无环。位置 L2 · R-MKT
偏差 · 不平衡imbalance
measured 与 cleared/schedule 之差，按不平衡费结算。图 4 ⑧ 的 L3 用同一规则集出具"偏差证明"。位置 计量/结算

§8校验与治理概念

校验服务validator
读 L0+L1(+L2)、按规则集判定、写 L3 的无状态确定性程序。可有任意多个、由不同方运行。只输出 verdict 与 violations，不输出指令。位置 图 1 下 · 图 3
确定性 · 无状态
同样输入、同样规则版本 → 同样输出，且不依赖此前的任何请求。这两条是"任何人可复算"的前提。位置 图 3
规则集rule set
标准的可执行部分：一组有稳定 id、版本、输入层、输出字段与测试向量的判定规则，分 R-PHYS / R-ENV / R-MKT / R-AGG / R-CONSENT 五组。明确排除任何"是否最优""应如何改"的判定。位置 图 3 ③ · §6 表
规则集注册表
存放各版本规则与其测试向量的公开仓库。L3 记录所用版本；复算时从此拉取同版规则。它是整个体系中需要被信任的两处之一（另一处是透明日志）。位置 图 3 下
一致性测试向量conformance test vectors
成对的"输入 → 期望输出"文件。"符合标准"的唯一定义就是对全部向量产生期望输出。位置 治理
verdict · violations
L3 的两个核心字段：结论（pass / fail / inconclusive）与违规清单，每条含规则 id、位置、残差、说明。violations 是开放数据集里"负样本"的来源。位置 L3
透明日志transparency log
只追加、哈希链式、公开可查的记录，仅存 L3 与输入哈希，不存任何明文。任何人可审计"某个 L3 确实在某时被记录且未被改动"。概念借自证书透明度（Certificate Transparency）。位置 图 1 右下 · 图 3
哈希链hash chain
每条记录包含前一条记录的哈希，改任一条都会使后续全部失效。只追加日志的防篡改基础。位置 透明日志
复算路径reproduce
第三方取 L3 中的规则版本 → 从注册表拉同版规则 → 用原输入重跑 → 比对哈希与 verdict。一致即证明成立；不一致则校验方作假或注册表被改。校验方本身不需被信任。位置 图 3 底
签名signer{id, alg, sig}
校验方对 L3 的数字签名。密钥属校验方，可多方。签名证明"是谁说的"，哈希证明"说的是哪份"。位置 图 3 ④
拓扑 A / B / C部署
A 边界内本地：明文不出边界，只有 L3 外发；B 托管：把数据发给第三方校验；C 多方交叉：同一输入送 ≥2 校验方比对。三者 L3 格式相同。位置 §8
数据驻留data residency
数据必须留在某个法律辖区内的要求。拓扑 A 与 consent.cross_border 共同满足它。位置 §8
开放数据集
仅在 consent.training_use=true 时，把脱敏后的 violations 汇入的公开数据集（CC BY 4.0）。它是校验体系对研究界的回馈，也是任何人（不限于某一方）训练模型的共同底料。位置 图 1 右下（虚线）
Profile标准的实施规范
在一个更宽泛的标准之上，规定"用哪一子集、怎么用"的窄化文档（如 CSIP 之于 IEEE 2030.5）。本标准自我定位为 S2 之上的聚合层 profile、Shapeshifter/CIM 之下的可行域与证明层。位置 治理
中立性硬约束
维护者中任一雇主不得占多数；规则变更须两个独立组织的实现通过测试；不成立新联盟；ext 无独占。这些是写进治理文件的规则，不是承诺。位置 §9
退出条款
若既有标准吸收了约束集表示与证明对象，本标准转为兼容层并冻结。"被吸收后消失"被定义为成功的一种。位置 §9
Flexibility envelope灵活性包络 · 术语来源◆
Nosair & Bouffard（IEEE Trans. Sustainable Energy 6(3), 2015）提出：用「时间约束下可部署的功率/能量范围」同时表达系统对灵活性的需求与资源能提供的灵活性 [A1]。后续扩展到配电网 [A2] 与能源社区 [A16]。本标准的 L0 与此同名同义。位置 命名依据
Realizability可实现性◆
聚合可行域中的一点能否真的分解到各成员、且每个成员都满足自身约束。近年文献（Elsaadany / Almassalkhi / Tindemans 2025；arXiv 2606.01562, 2026）给出电池群聚合可实现性的线性充分条件 [A4][A5]。对应本标准：aggregation.approximation=inner + 规则 agg.sum。位置 §4 · R-AGG
Polymatroid / zonotope聚合可行域的精确与近似表示◆
广义拟阵（generalized polymatroid）可精确刻画某类能量受限负荷的聚合可行域 [A7][A11]；约束 zonotope 用于电网感知的多时段聚合近似 [A10]。它们是 L0 约束集之上的「更紧表示」，可作 aggregation.method 取值。位置 L0 aggregation
CSIP 认证SunSpec IEEE 2030.5 certification◆
SunSpec 联盟运营的 IEEE 2030.5 CSIP 一致性认证；CSIP 从 2030.5 中选取 18 个功能集并规定实现方式。近期数据 52 家公司 77 项认证 [E2]；CSIP-AUS 有独立测试认证手册 [R12]。本标准一致性测试的组织形式可参照。位置 治理 · 资源侧
Network Code on Demand Response欧盟需求响应网络准则◆
ACER 2025-03-07 向欧委会提交的欧盟统一网络准则，使需求响应、储能、分布式发电全面参与批发市场；成员国须在 2026-07 前完成国家灵活性需求评估，2027-01 前设定指示性目标 [R6][R7]。L2/L1 在欧洲的制度落点。位置 市场侧 · 欧洲
FERC Order 2222◆
美国联邦能源监管委员会 2020 年命令，要求各 RTO/ISO 允许 DER 聚合体参与批发市场；各区实施进度不一（ISO-NE 能量/辅助服务市场定于 2026-11-01）[R10]。美国版「聚合商 ↔ 批发市场」制度。位置 市场侧 · 美国
虚拟电厂 指导意见（2025）发改委 · 能源局◆
2025-04-08《关于加快推进虚拟电厂发展的指导意见》：定义 VPP 为聚合分布式电源、可调节负荷、储能的运营组织模式；目标 2027 年 >20 GW、2030 年 >50 GW [C7]。GB/T 44241 与三份团标是其技术落点。位置 市场侧 · 中国
DCFlexEPRI 数据中心灵活性倡议◆
EPRI 2024 年启动的三年计划，>40 家参与（Google、Meta、Microsoft、Duke Energy、PJM 等），实测需求响应、负载转移、UPS 作为电网资源 [R2]。数据中心作为「站点」级 Envelope 的现实试验场。位置 资源侧 · 数据中心

§9附：相邻页面（战略审查 / 核实记录）出现的日本市场术语

同時市場どうじしじょう★
日本正在设计的未来市场：把电能（kWh）与调节力（ΔkW）放在同一个市场里同时出清，取代现行的现货市场 + 需给调整市场。目标 2030 年代前半启用，五阶段路线图。由経済産業省下属检讨会与 OCCTO 设计。
Three-Part Offerスリーパート・オファー★
同時市場的报价形式：按发电机登记 ①起動費（可按停机时长分档）②最低出力費用 ③阶梯式增分費用カーブ，加上運転パラメータ（出力上下限、起動時間、出力変化速度等）。源自北美市场。字段清单尚未最终确定。
SCUC / SCED★
Security Constrained Unit Commitment / Economic Dispatch：考虑电网安全约束的机组起停组合与出力分配优化，北美市场的出清方式，同時市場拟采用。
需給調整市場じゅきゅうちょうせいしじょう★
日本现行的调节力（ΔkW）采购市场，2024 年 4 月起全部五种商品上市；出现过约定量大幅低于募集量、价格高企的问题。
特定卸供給事業とくていおろしきょうきゅうじぎょう◆
日本电気事業法中"聚合商"的法定名称：从发电事业者以外的、拥有供给能力者处集约超过 1,000 kW 电力，供给给一般送配电/售电等。届出制（备案），2022 年 4 月起。纯校验服务因不供电、不集约而不属此类；边界在法条中的"指示"一词。
ブロック入札block bid★
JEPX 现货市场中把多个时段捆绑、全量成交或全不成交的报价。监管方数据：卖方报价中 60–80% 为 block，成交率仅数个百分点。
計画値同時同量けいかくちどうじどうりょう◆
日本的平衡责任制度：发电/需求平衡组须使实际值与提交的计划值一致，偏差按不平衡费结算。对应欧洲的 BRP 义务。
JEPX · OCCTO★
JEPX：日本卸電力取引所，唯一的批发电力交易所（现货 30 分钟 × 48 时段、区域价格）。OCCTO：電力広域的運営推進機関，全国电力事业者强制加盟的协调机构，运营容量市场与需给调整市场、汇总供需计划。
経済安全保障推進法 · 基幹インフラ制度★
日本 2022 年法律及其关键基础设施制度：指定的电力事业者（含聚合规模 ≥50 万 kW 的特定卸供給事業者）导入"特定重要設備"（含 EMS 及其软件）前须提交计划书接受审查，审查项包括供应商属性。
