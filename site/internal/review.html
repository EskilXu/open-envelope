§1一句话

OpenEnvelope 把"一段时间内一台（或一群）设备能做什么"写成一个可交换、可校验、可签名的对象；免费开放的是格式与判定，收费的是决策，沉淀的是别人用你的格式喂回来的结构化负样本。

它不是产品，是产品的入口和护城河的地基。它的价值不能用直接收入衡量，只能用三件事衡量：有多少外部系统写出了这个格式、有多少校验请求带着真实越界样本回来、以及当同時市場 2030 年代前半定稿字段时我们是否已经坐在桌边。

§2标准是什么：四层，各自独立

HDEB 把物理、市场、层级、回退、来源压在一条记录里。OpenEnvelope 把它拆成四层，每层可独立传输、独立版本。一个 EMS 只实现 L0+L1；交易所接口只实现 L2；校验服务读 L0+L1、写 L3。

三个设计承诺值得单独说明。第一，灵活性是约束集不是字段集：L0 用线性约束加少量命名参数表达可行域，FlexMeasures 的 flex-model 字段与 S2 的 FRBC 都能无损落进去，换设备类型不必改 schema。第二，验证是一等对象：L3 记录用哪版规则对哪个输入哈希得到什么结论，任何人可重跑。第三，同意显式：每个 Envelope 带 consent{cross_border, training_use, retention_days}，默认全部最保守。

§3设计审查：站得住的与站不住的

以下是把自己当审稿人给出的判断。每条附 verdict。

HOLDS
L0 空位真实存在。FlexMeasures 用命名字段（power-capacity、soc-minima、group、S2 power bands）内部编成 MILP，约束集本身不可交换 ★。S2、Shapeshifter 是消息协议。学界有 polytope/zonotope 表示但无交换格式。这是可以填的洞，不是想象出来的洞。
HOLDS
L3 与法律边界重合。特定卸供給事業的定义是"集约并供电"，法条里的关键词是"指示" ◆。只输出 verdict 不输出 instruction，既是商业分界也是监管分界。这种重合极少见，应当写进服务条款并作为对外叙事的核心。
HOLDS
命名跨语言零摩擦。flexibility envelope 是学界既有术语；運転エンベロープ、可行域包络在日中都是现成工程词；对齐 OpenADR/OpenSTEF/OpenLEADR 家族；GitHub 与能源标准域无撞名（2026-09-04 检索）。
WEAK
线性约束集装不下同時市場的核心。已修正 · schema 0.0.3 modes / 架构 env.mode Three-part offer 的起動費、最低出力、最小稼働/停止時間本质是整数/逻辑约束（开/关、模式切换）★。当前 L0 只有 A·u ≤ b，表达不了。必须在 0.0.3 加入 mode/binary 变量（可借 S2 OMBC 的 operation-mode 语义），否则 L0 对日本最重要的市场场景是残缺的。这是本审查发现的最大设计缺陷。
WEAK
层级聚合 aggregation_of 语义未定义。已修正 · aggregation.approximation ∈ {inner,outer,exact} 多个 Envelope 聚合成一个上层 Envelope 在数学上是 Minkowski 和，一般不精确、不可逆。若不写明"上层是内近似还是外近似"，两个实现会得出不同的可行域，一致性测试无法判定。
WEAK
consent 是 schema 字段，不是执行机制。字段能声明意愿，不能阻止滥用。没有配套的数据处理协议和审计日志，consent 只是一个好看的 JSON 键。需要一个最薄的"consent 一致性检查"进一致性套件：任何把 training_use=false 的数据写入训练集的实现即不合规。
RISK
标准墓地。能源领域的开放格式绝大多数死于"只有提出者一个实现"。当前外部实现数 = 0。所有战略价值都以"至少一个非本方 EMS 写出 L0"为前提。这不是设计缺陷，是存在性风险，见 §7 标记 M1。
RISK
HDEB 的血缘。桥接格式沿用了第三方白皮书的术语。已在 NOTICE 声明改名承诺，但公开仓库先以 HDEB 名字出现，会让日本审查方和欧洲社区先读到"深度动力"再读到"中立"。建议公开时 直接以 openenvelope 为主仓库，hdeb-open 作为其中的 compat/ 目录或私有。

结论：OpenEnvelope 不与任何一个竞争，它是这四个之间缺失的通用中间表示。这既是它能被接受的原因，也是它难以被注意到的原因——中间层没有自己的用户，只有别人的用户。所以 §5 的业务设计必须给它一个"自己的用户"。

§5业务与影响力：入口、飞轮、桌位

入口：免费校验，不免费决策

第一个对外产品不是预测或投标建议，是校验器：客户把计划用 L0+L1 发来，我们返回 L3。对客户零风险（不接管控制），对我们零法律负担（不"指示"），每一条请求都是结构化的。付费层是"怎么改"——优化、反事实、回退策略——那是物理层 14B 权重的工作。

口碑：开放的是可复核性，不是代码

电力行业不信 demo，信"我能自己重跑你的数字"。每季度公开一个复现榜：用 OPFData、RL2Grid 等公开数据集跑校验器与公开 baseline，结果、脚本、失败案例全放出来。这直接对应经济安保法审查看重的"可审计、供应商可识别"，也是对 Emerald AI–JERA 这类先发关系的反向定位：他们卖的是闭源结果，我们卖的是可复核过程。

桌位：2030 年代前半的字段定稿

同時市場第二次中間取りまとめ给了一个官方数字：スポット売り入札中ブロック入札占 60–80%，約定率仅数% ★。这是监管方自己量化的"能量块表达能力不足"。当详细设计开始定 DER 的投标形式（§6.6 待检討，脚注 15 "複数の電源をまとめて入札もありうる"）时，桌边已有一个开源的、有外部实现的、能表达约束集的格式，与桌边什么都没有，是两种截然不同的谈判位置。这是 OpenEnvelope 最大的单项期权价值，也是最难量化的。

首批用户：阈值以下的聚合商

经济安保法基幹インフラ制度只指定 ≥50 万 kW 的特定卸供給事业者。阈值以下的聚合商没有審査负担、有重写投标管道的痛点、数量多。免费校验 API 的首批用户就是他们；积累到"被审计过的供应商"身份后再上探大聚合商。

§6投入产出：以期权定价，不以收入定价

§7风险与可证伪标记

每条标记有时限、有明确 pass/fail。到期后在后续会话中标为 confirmed 或 falsified，不许改口。

M1 · 2026-12-31
至少一个非本方系统写出合法的 L0 Envelope（FlexMeasures 导出 PR 合并、或任一聚合商 EMS 发出）。Fail → 不进 P2，仓库转为个人研究项目。
M2 · 2027-01-31
L0 支持 mode/binary 且通过一致性用例能表达"最小稼働時間 + 起動費"。Fail → 承认 OpenEnvelope 不适合同時市場 L2，只做 S2 之上的聚合 profile。
M3 · 2027-03-31
LF Energy sandbox 申请得到正式回复（接受或书面拒绝均算 pass；无回复算 fail）。
M4 · 2027-06-30
3 家阈值以下聚合商中 ≥1 家连续 8 周发送 L1 到校验器，且至少 200 条 L3 verdict=fail 带 consent.training_use=true。Fail → 飞轮假设被证伪，保留标准、放弃数据积累叙事。
M5 · 2027-12-31
同時市場详细设计公开资料中出现 DER 集约投标的字段定义。这条不是我们能控制的，但决定 L2 日本 profile 何时能定稿；若晚于此日，桌位价值顺延而非消失。

三条不进标记但要盯的风险

单一维护者 结构性

今天全部代码与文档出自一人一日。基金会不会接纳单维护者项目。P1 至少需要一名外部 co-maintainer，哪怕只维护一致性测试。

许可被稀释 治理

Apache-2.0 + CC BY 4.0 是对的，但若日后为了商业层引入"开放核心"式的字段（只有付费版能读的 ext），中立性叙事立刻崩塌。规则：ext 命名空间任何人可注册，本方不得独占。

血缘被读出来 叙事

日本审查方会看仓库历史。hdeb-open 的名字和 NOTICE 里的说明，在中立性上是负资产。建议公开顺序：openenvelope 先，hdeb 作为兼容目录后。
