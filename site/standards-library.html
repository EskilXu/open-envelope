OpenEnvelope 标准库

把 OPC Foundation、LF Energy、IEC/IEEE 与中国 GB / DL/T / 团体标准按四层归位，作为可贡献、可测试的映射库来设计

§1为什么是"库"，不是"又一个标准"

灵活性资源领域不缺标准，缺的是它们之间的对象级对齐。标准库的定义：一个开源仓库，登记每个既有标准，给出它到四层对象（Envelope / Position / Offer / Attestation）的字段级映射、测试向量与访问性说明；映射本身受一致性测试约束。

三条设计约束决定了它的形态。第一，多数既有标准是付费文本（IEC、DL/T、IEEE），库只引用字段名与语义，不复制文本。第二，映射必须可测：每条映射带成对的输入/期望输出向量，实现通过向量即"符合"。第三，中国标准体系通过采标与 IEC 在信息模型层重合、在业务层分叉，库的结构要能同时表达"复用"与"独有"。

§2三个生态 × 四层：一张图看重合与空位

结构性发现：中国标准体系不是一个平行宇宙。设备与电网模型层它就是 IEC；分叉发生在"聚合以上"——虚拟电厂、需求响应、现货规则。这恰好也是 OpenEnvelope 的 L0 聚合语义与 L2 所在的层。因此库对中国的工作量集中在 cn-vpp、cn-dr、cn-market 三个 profile，而不是重做设备层。

§4中国标准的四个结构特征（决定 profile 怎么写）

采标层可直接复用

DL/T 860 与 DL/T 890 是 IEC 61850 与 61970 的等同/修改采用。SCL 文件、逻辑节点、CIM 类名在中国部署中原样存在。库对这两层不写 cn 映射，只在 NOTES 里记录采标版本差异（如 61850 Ed.1 vs Ed.2）。

VPP 层是"管理规范"而非"接口规范"

GB/T 44241 定义的是虚拟电厂是什么、资源怎么分类评估、怎么管理；接口细节落在团标（T/CITS 195 给通信架构与协议）。因此 cn-vpp profile 的主要工作是：把 44241 的资源分类与可调能力评估指标映射为 L0 的 params 与 bounds，把 T/CITS 195 的数据要求与接口映射为 L0/L1 的传输绑定。

市场层是规则文件，不是数据标准

现货市场"基本规则 + 各省细则"以政策文件形式存在，报价格式由各交易中心技术规范定义 ◇。cn-market profile 只能做到：L2 的通用字段 + 每省一个 ext["cn.market.<省>"] 子命名空间，字段由该省交易中心公开文档决定。

安全与驻留是硬约束

GB/T 36572 的安全分区（生产控制大区 / 管理信息大区）决定校验服务只能部署在拓扑 A（边界内）；数据出境评估把电力运行数据视为重要数据，因此 consent.cross_border 在中国默认恒为 false，且开放数据集的脱敏规则需单独审查。

由此得出一条工程结论：面向中国的实现，设备层零新增、聚合层一个 profile、市场层按省扩展、校验层只能本地部署。这与图 1 全景的"校验是旁路"设计是相容的——旁路可以整个搬进边界内。

  profiles/
    iec/s2/                 mapping.yaml · vectors/ · NOTES.md
    iec/61850/
    iec/62325/
    opc/ua-envelope/        EnvelopeType companion 草案 (NodeSet2.xml) · mapping.yaml
    lfe/flexmeasures/
    lfe/shapeshifter/
    lfe/cupid/
    lfe/everest/
    cn/vpp/                 GB/T 44241 + T/CITS 195 + T/CIEP 0261 + T/BEPIA 001 → L0/L1/L2
    cn/dr/                  GB/T 32672 + 负荷管理系统 → L1/ctx
    cn/ess/                 GB/T 36547/36548 → bounds · 测试向量
    cn/der/                 GB/T 33593 → bounds
    cn/market/              现货基本规则 → L2；ext["cn.market.<省>"]
    cn/NOTES.md             采标对照（DL/T 860 ↔ 61850 版本）· 安全分区 · 出境
envelope/                四层 schema · 规则集 · 一致性向量（库的"目标端"）
tools/                   校验器 · 适配器参考实现

mapping.yaml 的每条映射是一个五元组：源字段、目标层与字段、单位换算、缺省值、是否有损。库里实际的 S2 → L0 节选：

source: {standard: iec.s2, version: "1.0", object: FRBC.SystemDescription}
target: {layer: envelope, version: "0.0.3"}
fields:
- from: actuator_descriptions[].operation_modes[].elements[].power_ranges[]
  to: bounds.p
  note: 取各模式并集为外框；模式细节进 modes[]
- from: actuator_descriptions[].operation_modes[]
  to: modes[]
  note: OMBC/FRBC 模式 → mode 变量；transitions → env.mode 最小持续时间
- from: storage.fill_level_range
  to: params.storage.soc_min/soc_max
  unit: fraction
- from: (none)
  to: consent
  default: {cross_border: false, training_use: false, retention_days: 0}
lossy_back: true   # L0 → S2 会丢失非模式类耦合约束

一条映射被接受的条件只有一个：vectors/ 里至少一对输入/期望输出，且参考适配器跑通。没有向量的映射是意见，不是库的内容。

§7访问性与许可：库能放什么、不能放什么

可以放

字段名、枚举值、单位、结构关系（这些是互操作所必需的"接口事实"）；GB/T 全文公开系统可免费阅读的国标的条款引用；开源项目（LF Energy、s2-json、CSIP）的 schema 引用；本库自己写的映射与向量。

不能放

IEC、IEEE、DL/T、团标的正文复制；付费标准的表格整段转录；任何标注"内部"的企业技术规范内容。向量里的示例数据须为自造或明确许可的公开数据。

命名

标准编号与名称可自由引用（事实）；OPC UA、OpenADR 等为各自组织的商标，只作互操作对象引用，不用于本库自身的名称或宣传。

中国团标的特殊性

T/ 标准由社会团体发布，文本通常付费或会员获取；但其范围与目次在国家标准馆公开。库只登记范围与接口位置，字段级映射需取得文本后由贡献者以"引用字段名"方式提交。
